# AI 建筑师：只增不改的第一期合同

## 目标与边界

驻镇建筑师「筑一」使用 LLM 为小镇设计新工程。第一期生成的是**受约束的模块化建筑方案**，不是让模型执行代码或任意改造地图。

- 模型默认复用小镇现有服务端 DeepSeek 配置：`deepseek-flash`（产品展示名 DeepSeek V4.1 Flash）。
- 模型只返回名称、设计说明、核准地块、建筑类型、配色与朝向。
- 渲染器负责实际造型；模型不能上传资源、写 JavaScript/HTML、给出 URL、坐标或任意几何参数。
- 新工程追加到独立账本。没有更新、删除、搬迁、替换既有工程的 API。
- 原有道路、喷泉、地标、小游戏和居民活动路线不交给模型控制。
- 一段描述不会自动变成新小游戏或可运行的建筑业务逻辑；那属于后续明确开发范围。

## 每日自主工程与逐次审批

以**北京时间自然日 00:00**划分，全镇共用一处自主工程尝试，不是每位游客、每个房间或每个 IP 各有一处。

1. 服务成功监听后启动轻量调度器，每 60 秒检查一次。
2. 当天还没有自主尝试，且有安全空地时，建筑师自行构思并设计一处。
3. 游客也可以主动发起当天尚未使用的自主工程；API 和调度器竞争同一笔原子日额度。
4. 当天后续工程必须输入正确审批密码，且**一次审批只授权本次一处工程**。
5. 密码验证发生在收费模型请求之前；错误密码不会调用模型。
6. 同一游客身份下，同一请求编号及相同建议可恢复原结果，不重复调用模型；同一编号改写建议会被拒绝。
7. 刷新页面、换房间、换游客身份、换 IP 或重启服务都不会重置全镇日额度。

**失败也消耗当天这一次自主尝试。**这是防止故障或不合规模型输出导致后台无限收费重试。超时、格式不合规或服务中断后，当天不会自动再次设计；若玩家仍想生成另一处，需单独审批。该规则应在界面明确显示。

额外工程不是无限授权：每个新请求仍须独立审批。重复取回已完成请求不需要再调用模型，也不会新建另一处。

每处建筑及附属装饰必须在地块中心 `X/Z ±2`、高度 `0–7.5` 的包络内。朝向只能为 0/90/180/270 度；碰撞保留额外 0.25 单位边缘。模型不能突破此包络。

## 数据与接口

模型计划的严格字段：

```json
{
  "version": 1,
  "name": "海风书屋",
  "description": "给巡游归来的旅人一处安静读书的地方。",
  "plotId": "plot-1-1",
  "kind": "reading_room",
  "palette": "coastal",
  "orientation": 0
}
```

示例只是数据格式，不是默认生成结果。名称 1–24 字，说明 1–180 字，均为单行普通文字。未知字段、控制字符、代码/HTML/URL、未知地块和不在枚举中的值会被拒绝。服务器在模型返回后、事务提交前再次验证地块仍未占用。

- `GET /api/architect/status`：公开、只读，返回 `enabled/model/day/resetAt/autonomousUsed/phase/projects/latest/availablePlotIds/approvalRequired` 等状态，不调用模型。
- `POST /api/architect/generate`：需要既有签名游客 token，接受 `token/idempotencyKey/brief/password`。`brief` 可留空；密码仅本次超额审批使用。
- 成功返回 `{project,replayed,status}`。公共工程为 `{id,createdAt,day,source,plan}`；`source` 是 `autonomous` 或 `approved`。
- 错误只返回固定的 `code/error/message`，不回显上游正文、密钥、密码、散列值或基础设施路径。
- 客户端状态轮询只读账本，不能借刷新触发模型；失败或超时不自动重试生成。

## 工程参观

工作室提供「找到筑一」，每处已建工程提供「前往工程」。按钮统一走既有 `travel` 流程：

- `architect`：到建筑师旁的安全位置，而不是角色中心。
- `architect-project:<已建工程 id>`：必须先在只追加的、已校验的世界注册表中找到工程，再选择建筑包络外的安全邻点。
- 浏览器和服务器使用同一份 `getDestination`；不接受客户端坐标、裸地块编号或尚未建成的工程。
- 到达点有 0.45 单位角色空间检查；优先建筑正面，若贴近树等障碍则尝试其他方位。
- 船上仍禁止前往其他地点；必须靠港下船，不能用工程参观入口绕过航行状态。
- 参观和刷新都不调用模型。

## 服务端配置

以下全部是**配置项说明或占位符**，不是实际部署凭据：

| 环境变量 | 含义 |
|---|---|
| `ARCHITECT_ENABLED` | 仅显式 `true` 开启生成；默认关闭 |
| `ARCHITECT_AUTONOMOUS_ENABLED` | `false` 关闭后台自主调度，供测试/维护使用；不自动释放已经占用的日额度 |
| `ARCHITECT_DB` | 独立持久化 SQLite 路径，例如 `/absolute/private/path/architect.sqlite` |
| `ARCHITECT_APPROVAL_HASH` | 私密配置中的 scrypt 散列占位，不是明文密码 |
| `ARCHITECT_TIMEOUT_MS` | 合法整数 1000–45000 毫秒；默认 45000，超出上限会收紧 |

必须同时具备显式启用、有效审批散列和有效既有 NPC LLM 配置，否则生成关闭。沿用服务端 `npcLlmConfig`，不复制密钥到浏览器，也不读取或解密其他项目凭据。

模型协议使用 OpenAI 兼容 `/chat/completions`，`response_format: {"type":"json_object"}`、`thinking: {"type":"disabled"}`、`stream:false`、`temperature:0.2`、独立 `max_tokens:1500`。这些是本模块参数，不改变 NPC 对话参数。

审批散列使用已有服务器 scrypt 算法和常量时间比较。必须通过私密部署配置提供；禁止把明文密码、真实散列或模型密钥写入源码、文档、前端环境变量和开源仓库。验证失败同时按 IP 与游客限速，并约束并发散列计算。

数据库必须独立于 AI 演出/人物工坊/NPC 数据库，且位于发布目录之外的持久化位置，不能随一次 release 替换或回滚丢失。服务重启读取既有工程；关闭生成仍保留已建工程。

## 只增不改的实现

- `shared/architectPlan.js`：白名单、固定地块及严格计划验证。
- `shared/architectWorld.js`：只追加的动态世界投影；旧快照或空数组不会删掉已知工程，重复 ID/占用地块不能被改写。
- `server/architect/store.js`：独立 SQLite 全镇账本，`BEGIN IMMEDIATE` 原子抢占，日期唯一键、项目地块唯一键和请求幂等。
- `architect_projects` 表包含阻止 UPDATE/DELETE 的触发器。请求状态可以记录完成/失败，但已建工程数据不可变。
- `server/architect/service.js`：一次请求最多一次模型调用、完整超时、有限响应体、验证后追加、后台日调度与关闭清理。
- `server/architect/access.js`：仅服务端审批；密码不落入工程记录，不进入模型提示词。

这套边界约束的是应用和模型可用能力；拥有服务器数据库管理员权限的人不属于 LLM 授权边界。
